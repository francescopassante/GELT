## 2. The confirmed defect: Z₂ APE smearing

`z2_fair_fight.py`'s docstring records a pre-flight finding from 2026-08-17.
This audit re-derived it independently, on production configurations, and it is
**worse than the pre-flight stated**.

### 2.1 The mechanism

In 3D with spatial-only smearing there are two staples, so
`V = (1−α)U + (α/2)(s₁ + s₂)` with `U, sᵢ ∈ {±1}`:

    s₁ + s₂ =  0  →  V = (1−α)U        sign of U preserved, always
    s₁ + s₂ = ±2  →  V = ±α + (1−α)U   the staples win iff α > ½

So projected Z₂ APE smearing has **no tunable radius at any α**: it is the exact
identity below ½ and a majority-vote cellular automaton above ½, which reaches a
fixed point in a few sweeps. At α = ½ exactly, `V = 0` in precisely the cases
where the staples disagree with the link, and `Z2.project` sends `0 → +1` by its
`>= 0` rule — a value that does **not** transform, since covariance demands
`project(ω·0·ω′) = ω·project(0)·ω′`, which fails whenever `ωω′ = −1`.

`SMEAR_ALPHA = 0.5` is the production value in both `train_z2_glueball.py` and
`train_glueball.py`.

### 2.3 Blast radius

**SU(2) is clean.** Checked, not assumed: `SU.project` is the SVD polar factor,
continuous, no ties. Covariance violation **1.4e-15** at α = 0.5 and 6.1e-15 at
α = 0.7, and the ladder keeps moving (mean |ΔU| = 0.197, 0.087, 0.056, 0.042).
So `su2_fair_fight.py`'s prediction that the Z₂ defects are Z₂-specific is
**confirmed**, and the §6.2 headline — the thesis's core claim — is untouched.

**Z₂ is affected in three places.**

1. **The classical comparator is one operator, not four.** The ladder freezes
   after one step, so `SMEAR_LEVELS = [0, 4, 8, 16]` holds two distinct
   operators. The saved dump already recorded the consequence and it was never
   connected to the cause — `results/attention/z2_attention_correlator_diag_R6.pt`
   has `n_basis=4, n_ops=1, gevp_fell_back=True` **at all five β**. The paper's
   "optimal combination of a four-level smeared Morningstar–Peardon basis" is, in
   the Z₂ section, a single smeared operator at every coupling.

2. **The network's own inputs are degenerate and slightly gauge-variant.**
   `train_z2_glueball.py` sets `INPUT_SMEAR_LEVELS = (0, 4, 8, 16)`, and
   `z2_attention_correlator.py` overrides it only in smoke mode — so the Z₂ nets
   were trained *and* evaluated on four channels of which **three are
   byte-identical**, one of which carries 0.67% gauge-variant plaquettes. The
   abstract's "exact invariance of the network output is verified to machine
   precision" is true of the **architecture** (and `check_gelt_invariance.py`
   tests exactly that) but is **not** true end-to-end of the Z₂ input pipeline.
   This needs one sentence in the paper regardless of what the fair fight finds.

3. **The dual accuracy table is measured against a handicapped opponent.**
   `notes/dual_ground_truth.md` §7.7 reports classical −8.9%, attention-trained
   +3.8%, attention-random −8.0%. Gauge noise on an operator lowers A₀ and biases
   ξ **low** — the same direction as the classical deficit. This does not mean
   the result is wrong; the random-network arm shares the same inputs and lands
   at −8.0% without using the classical basis at all, which is a point in the
   result's favour. It does mean the comparison is not clean, and it is the first
   thing a referee will attack.

### 2.4 Why the tests missed it

`tests/test_glueball.py`'s covariance cases use α = 0.7 and α = 0.6 — never the
production α = 0.5. Adding that case is a two-line change and it will **fail**,
which is the point. It was deliberately *not* added during this audit: the
paper's acknowledgments cite the suite passing in full (111 tests), so turning
the suite red is a call for the author to make alongside the fix, not a
drive-by.

## 3. The new result

`notes/operator_decomposition.md` + `scripts/operator_decomposition.py`, written
during this audit. Short version: the learned operator has a component
**12.9% ± 0.4% / 11.7% ± 0.3%** (two independent ensembles) of its norm² outside
the span of the entire classical basis; that component carries 13–14% of the
ground-state amplitude; removing it costs the whole advantage
(**ΔA₀ = +0.076 ± 0.019, 4.0σ** combined, at unchanged mass); and it is not a
contact term (the fraction *grows* under the C(τ) metrics, 0.129 → 0.156 →
0.197). The classical ladder's own increments — 0.689 → 0.197 → 0.049, a
converged geometric series replicating to the third decimal across ensembles —
supply the scale that makes 13% meaningful.

It reproduces the published GELT-vs-GEVP numbers exactly as a gate. Its two
missing controls and its one falsifiable prediction about the fair fight are in
that note's §5 and §6.

## 4. Plan, ranked

1. **Run both fair fights on the V100.** They are written, they smoke-test
   clean, and until they run the Z₂ accuracy table has a known, self-diagnosed,
   unanswered hole. `z2_fair_fight.py` needs a GPU plus the cached Z₂ ensembles
   (present). `su2_fair_fight.py` needs
   `datasets/glueball_configs_L12_Lt24_b2.4_xi3.0_N2000.pt` — check the V100
   before re-sampling.

2. **The random-init control for the decomposition.** One GPU eval pass, no
   training. It is what separates *learned* from *architectural* in the new
   result, and it is pre-registered in `notes/operator_decomposition.md` §5.
   Highest value per GPU-hour currently available.

3. **Fold the decomposition into `su2_fair_fight.py`**, decomposing against
   `full` rather than the published basis. The two studies constrain each other;
   run together they answer both "was the opponent strong enough?" and "is the
   win outside the opponent's reach?".

4. **Fix the Z₂ smearing and cover it.** Either α = 0.7 (covariant, real
   ladder) or the unprojected fat links `z2_fair_fight.py` already implements
   (linear in the links, hence exactly covariant, and the only Z₂ scheme with a
   tunable radius). Add the α = 0.5 covariance case to `tests/test_glueball.py`.
   Note this changes the Z₂ *inputs*, so a clean end-to-end statement needs a
   retrain; evaluating the existing checkpoints on covariant inputs is the cheap
   robustness check to do first.

5. **Dump per-config Ō arrays from `z2_attention_correlator.py`.** It currently
   saves summary dicts only (`m`, `m_err`, `profile`, …), so the decomposition
   cannot be transported to the attention field without a GPU re-run. One extra
   key in the saved blob removes that dependency permanently.

6. **Housekeeping.** Merge `dual-ground-truth` → `main`; `git add` the two
   fair-fight scripts before their docstrings are lost; add
   `notes/operator_decomposition.md`, `notes/audit_2026-09-06.md` and the
   fair-fight scripts to `CLAUDE.md` and `results/README.md`.
